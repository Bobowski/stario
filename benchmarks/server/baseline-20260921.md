# Server benchmark capture (2026-09-21)

Single-worker comparison of **this checkout at the time** (`stario` Python
httptools vs `stario-cython` llhttp on `cython-core` before the 4.2 merge)
against native HTTP servers and ASGI stacks on the reshaped suite: one static
page, one request-field GET, then async uploads from a small JSON object up
through buffered / streamed / multipart bodies.

Relative signal on one machine — not lab-grade absolutes. Numbers are **not
comparable** to `baseline-20260827.md` and earlier: those used a cached
`/user/42`, per-request JSON encodes, and GET handlers that never `await`ed.

## Reproduce

```bash
DURATION=10s RUNS=5 WARMUP=1 THREADS=2 \
  CONNECTIONS=128 UPLOAD_CONNECTIONS=32 \
  PYTHON=3.14 WRK=wrk \
  benchmarks/server/run.sh
```

Run directory: `benchmarks/server/results/20260921T092707Z` (gitignored).

## Methodology

- One worker/process per target.
- Endpoints: `plaintext`, `request`, `json-small`, `post-octet-64k`,
  `post-octet-2m`, `post-stream-2m`, `multipart-2m`.
- **5 measured + 1 warmup**, `DURATION=10s`, IQR trimming via
  `benchmarks/server/stats.py`.
- Static `/plaintext` returns a prebuilt body. `request` interpolates path
  param `user_id`, query `q`, and header `x-request-id` into a plain line
  (wrk working set 4096). Every upload handler reads the body then
  `await asyncio.sleep(0)`.
- Responses are **plain text** so JSON serializers cannot win a case.
- `wrk` `Requests/sec` only. wrk outputs were scanned for `Non-2xx`; the
  only errors were Robyn `request` (see below).

**Robyn `request`:** the first pass returned 5xx on every request
(`QueryParams.get` requires a default; `Headers.get` does not take one).
That row is a **re-run** after the handler fix (`17,074 ± 49`, no Non-2xx).
Other Robyn endpoints are from the original pass.

| Robyn | 23,377 ± 247 | 17,074 ± 49 |

Plaintext on this host is a ~148k band shared by Stario (both backends) and
Granian RSGI. That is likely a wrk / 4-vCPU loopback ceiling for a prebuilt
body, not a protocol gap: Python vs Cython is inside noise (±5–7k).

Request fields drop everyone except Granian. Granian has no router and
parses path/query/header by hand, so it stays near the plaintext band
(140k, **1.30×** Stario). Stario is the fastest frameworked server on that
case (**3.3×** FastAPI, **1.73×** BlackSheep+Granian).

2MB **stream** case (native chunk callbacks). Stario stream is a close
second (~3.5k vs 3.6k).

## Stario Python vs Cython

Tied on this suite. Static plaintext is ceiling-limited; request fields and
uploads spend their time in Python routing, `await sleep(0)`, and body
plumbing. Treat ±5–7k plaintext stdev as noise.

## Notes

- Robyn and Django-Bolt buffer the stream route (no request streaming API).
- BlackSheep+Granian vs BlackSheep+Uvicorn shows the server: Granian is ~2×
  Uvicorn on static plaintext (118k vs 59k) with the same app.
- High plaintext stdev on Stario is the same 4-vCPU contention pattern as
  earlier captures on this machine class.
